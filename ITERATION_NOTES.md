# Iteration Notes

## Goal
Make RGB profiles capabilities-aware: one profile spec renders a unified color theme across all devices via a capabilities.json table (wireless SL-INF 8/36 split, wired AL V2 8/12 split, motherboard JRAINBOW1 72 LEDs, RAM), with persistence that never reverts to rainbow

## State
Iteration 4 (of many): validate.sh now enforces that device ids come from capabilities.json — no hardcoded literals anywhere outside it. New "Device ids sourced from capabilities.json" check: (1) greps every scripts/*.sh for wireless-MAC / `hid:...:groupN` literals and fails if any appear; (2) parses config.json for all device_ids and fails if its wireless/group ids diverge from capabilities.json's instance ids (drift check — catches stale config after a capabilities edit). Check is offline-safe (pure JSON/script scan, no daemon needed), prints FAIL lines to stderr, sets FAIL=1, only prints OK on success. Verified: bash -n clean, clean repo run passes (ALL CHECKS PASSED), negative tests fail correctly (planted literal in a script -> flagged; foreign wireless id appended to config.json rgb.devices -> flagged + exit 1).

NEXT: remaining refactors to RENDER from capabilities.json:
1. `config.json` wireless entries in `fans.speeds` + `rgb.devices` still carry the MAC literals + 44-length arrays. The new drift check confirms they currently MATCH capabilities.json, but `fans.speeds` is NOT regenerated by `lianli-profile.sh` (only `rgb.devices` is). Consider teaching `lianli-profile.sh`'s config rewrite to also reconcile `fans.speeds` wireless device ids from `$WIRELESS_DEVICES`, so a capabilities MAC change needs no manual config.json edit.
2. `lianli-fan-speed.sh` uses hardcoded curve arrays (wired_base/wireless_base) keyed by position (`fan_curves[0]`/`[1]`) — could read curve names from config.json instead of positional indexing.
3. Eventually collapse the profile spec: `wired.inner`/`wired.outer` already equal wireless colors on all 88 profiles — a capability-aware renderer can drop `wireless.inner_color/outer_color` redundancy.

GOTCHAS:
- `validate.sh` live checks (services/socket) need the daemon running; JSON checks are offline-safe.
- `lianli-capabilities.sh` must be sourced (not executed); it needs `readlink -f` so it works via `~/.local/bin` symlinks. The eval'd python emits quoted space-separated strings for device lists — do NOT switch them to bash arrays, the scripts iterate with `for dev in $WIRELESS_DEVICES`.
- Profile `wired` colors and `wireless.*_color` are identical across all 88 profiles (verified) — redundancy safe to remove later.
- Motherboard coloring assumes JRAINBOW1 is the FIRST `led_count` LEDs of the OpenRGB MOTHERBOARD device (replaced the old name-scan heuristic); if a board enumerates headers out of order, revisit with a per-header index map in capabilities.json.
